# 1. 从标准的Full Attention谈起

先把结论说透: Softmax 并不是随手拍脑袋想出来的, 也不是工程上的折中. 在数学上, 它本身就是最优解. 在"单位注意力预算 + 点积打分 + 保留熵"这三个前提下, 它是唯一解. 本节主线很清晰: 打分 → 缩放 → 归一化 → 加权平均, 每一步各司其职.

## 1.1 从缩放点积到概率单纯形

> 一句话总结: 点积负责打分,  $\sqrt{d_k}$负责稳住分数的尺度, Softmax 负责把分数变成一份总量为 1 的注意力预算.

对单个 Query $q$ , 先给每个可见 Key $k_1, k_2, \cdots, k_m$ 打一个相关性分数
$$
s_j = q^\top k_j, \tau > 0.
$$
分数可以是任意实数, 不能直接拿来当权重. Softmax 把它们转成
$$
p_j = \frac{\exp(s_j / \tau)}{ \sum_{l=1}^m \exp(s_l / \tau)}
$$
变换后的权重自动满足两个约束: 每一项非负, 且总和为 1. 满足这两个约束的向量构成了`概率单纯形`
$$
\Delta^{m-1} = \left\{ p \in \mathbb{R}^m | p_j \geq 0, \sum_{j=1}^m p_j = 1 \right\}
$$
$m=3$时它就是一个三角形, 任何分数向量都会被 Softmax 压进三角形内部. 这两个约束各自带来了一个好处.

_好处一_: 输出尺度稳定. 输出
$$
o = \sum_{j=1}^m p_j v_j
$$
是 Value 的加权平均 (凸组合), 永远落在这些 Value 围成的凸包里. 对比一下不归一化的求和$\sum_j \exp(s_j) v_j$ : token 越多, 数值越大, 看 1K 个 token 和看 1M 个 token 的结果根本不在同一尺度上. 归一化让输出尺度与序列长度解耦.

_好处二_: 竞争, 而不是各开各的门. 总和为 1 意味着所有 Key 共享一份固定预算, 想多给某个 Key 一点, 就必须从其他 Key 那里扣回来. "谁更相关"因此变成了一场零和竞争. 反例是独立门控: 每个位置各自过一个 sigmoid, 可以同时全开, 模型根本不需要做相对判断.

最后说缩放. 若  $q$和 $k$ 各维近似独立, 且零均值单位方差, 则
$$
\text{Var}[q^\top k] = d_k
$$
维度越高, 分数越散, 而  $\exp$会放大这种差距: 分数一散, Softmax 就提前退化成最高分独占 (one-hot), 梯度也随之集中和消失. 除以  $\sqrt{d_k}$后
$$
\text{Var}\left[\frac{q^\top k}{\sqrt{d_k}}\right] = 1
$$
方差与维度无关, Softmax 得以工作在"有区分度但不饱和"的区间. 这就是温度取 $\tau = \sqrt{d_k}$ 的缘由.

## 1.2 Softmax 是单边熵最优输运的唯一解

> 一句话总结: 以 Optimal Transport 的视角来看, 注意力可以理解为"运送 1 单位质量"的分配问题. 写清成本和正则后求解, 答案不多不少, 恰好是 Softmax, 而且是唯一的答案.

先建立图景. Query 是货主, 手里有 1 单位质量; 每个 Key 是一个目的地; 把 1 单位质量运到 Key  $j$的运费是负相似度$$
C_j = - q^\top k_j = -s_j
$$
即越相关, 运费越低.  $p_j$就是运到 Key $j$  的质量. 注意这里只固定了"货主总共发出 1 单位" ($\sum_j p_j = 1$), 不规定每个 Key 必须收多少, 所以叫单边输运. 这个"单边"很关键: 双边输运 (两端都有配额) 没有闭式解, 要靠 Sinkhorn 迭代; 单边则可以直接解出来.

要最小化的目标由两项组成:

两项方向相反, 构成一场拉锯. 第一项是总运费, 它单独最优时会把全部质量压到分数最高的那个 Key (退化成 argmax); 第二项是负熵, 它单独最优时会把质量摊成均匀分布. 温度  是拉锯的旋钮:  得到 one-hot,  得到均匀, 有限  则得到一个有主有次的折中.

最后是"唯一"二字.  的二阶导为 , 所以熵项严格凸; 加上线性的成本项不改变凸性, 目标整体严格凸. 单纯形又是凸紧集, 因此极小点存在且唯一. 结论是条件性的必然: 只要接受单位质量约束, 点积成本和 Shannon 负熵这三个前提, 归一化函数就只能是 Softmax. 想要别的机制, 就得改前提: 换正则得到 Sparsemax/Entmax, 缩小可行域得到 Sparse Attention, 放弃逐 Query 分布得到 Linear Attention.

## 1.4 必须使用 Softmax 不等于 Softmax 没有代价

> 一句话总结: 上面证明的是"在给定前提下 Softmax 唯一", 但这些前提本身并非没有代价. 这里有两个实际成本: 预算花不完时会出现 Attention Sink, 上下文变长时注意力会被自动摊薄.

**代价一:** 预算必须花完. 单位预算意味着每个 Query 必须把 1 分完, 哪怕这一层其实没什么值得关注的内容, 也不能输出全零权重. 训练的常见对策是让某个语义上无关紧要的 token (往往是开头的 token) 充当"垃圾桶", 吸收多余的概率 (即 Attention Sink). 这可以理解为单纯形约束下的一种 no-op 工程实现. 但它也带来了一个隐患: 截断窗口时如果把这个 Sink token 删掉, Softmax 的分母会突变, 即使高分 token 都还在, 整个分布也可能发生漂移.

**代价二:** 长度外推并非自动成立. 若所有 logits 落在固定区间 $[a, b]$, 则每个权重都被夹在

之间, 上下界都随  以  的速度收缩. 直觉是: 分数的"音量"有上限, 而分母里的竞争者越来越多, 每个位置分到的注意力只能是 . 想在百万 token 中保持同样尖锐的选择, logit 差距必须随  增长, 或者温度要跟着变化. 归一化和竞争固然是有原则的, 但固定温度下的长上下文外推并不是免费的午餐.

⚠️ 似乎这里有一个Adpative Temperature的机会.

另外, 改前提就得到别的机制. 这不是 Softmax 的失败, 而是换了问题. 把负熵换成二次正则 , 解就变成向单纯形投影的 Sparsemax, 权重可以精确为零; 用 Tsallis 熵则得到 Entmax. 本报告后面讨论的 Sparse Attention 走的是另一条路: 不换正则, 只缩小参与 Softmax 竞争的候选集合.

## 1.5 精确 Full Softmax 的全局依赖不能被普遍绕过

> 一句话总结: 每个 Query 的分母依赖于全部可见 Key, 想要普遍地少看又不出错, 在对抗性输入下是不可能的; Linear 和 Sparse 都是靠额外假设来换取加速.

问题出在归一化常数$Z_i = \sum_{j=1}^m \exp(q_i^\top k_j / \tau)$上: 它是全局的, 任何一个 Key 都影响所有权重.

needle in a haystack 式的论证把这一点变成了明确的结论: 假设某算法总共只检查$o(n^2)$  个 QK 对, 那么至少有一行 (某个 Query) 只被检查了 $o(n)$ 个位置; 对抗者只需在这一行没被看过的位置里塞进一个超高分数, 精确 Softmax 会把几乎全部概率给它, 而算法根本没看到这个位置, 自然无法区分"有针"和"无针"两个输入, 误差因此存在一个不会消失的下界.

这个结论要读得准确: 它并不是对一切计算模型的无条件下界, 而是说, 在允许对抗性输入, 不做分布假设, 且信息只能靠检查 QK 对获得的设定下, "普遍亚二次"和"渐近精确"不可兼得. 反过来, 这也解释了 Linear 和 Sparse 为什么能成立: 它们各自加了假设. Linear 假设历史可以被固定大小的状态压缩, Sparse 假设高质量的概率质量能被便宜的索引器提前定位. 假设成立时加速是真的, 假设破产时误差也是真的. 这是后续所有章节的比较基线.

# 2. 从 Softmax Attention 线性化到 GDN

上一节末尾留下了一个选择题: 不想为每个 Query 支付"看全部历史"的二次成本, 就必须改变信息处理的方式. 这一节我们先来看 Linear Attention. 苏老师写过一篇文章《将Softmax Attention线性化为Gated DeltaNet》[1], 本节内容是我就此整理的读书笔记.

本节回答的问题是: **从 Softmax 出发, 沿着什么样的推导路线才能走到 GDN (Gated DeltaNet) 这样的线性递推?** 路线图分四步:

- 2.1 先展示一条"笨路": 把整张注意力图一次性泰勒展开, 只能得到能力有限的 Vanilla Linear Attention
- 2.2 发现 Softmax 自己就藏着一个精确的 Delta 递推;
- 2.3 改为每步只近似一个数, 并尝试把 Query 从递推中拆出去;
- 2.4 处理拆分时冒出的障碍, 落地成 GDN 的形态.

核心信息用一句话概括: GDN 不是拍脑袋拼出来的门控 RNN, 而是 Softmax 精确递推在经过"局部近似 + Query 分离"之后自然呈现的形态.

### 2.1 全矩阵一阶展开只能得到 Vanilla Linear Attention

> 一句话总结: 一次性把全部$t^2$  个注意力权重都做一阶近似, 得到的就是 Vanilla Linear Attention. 它的三个毛病全部源于这一步下手太重.

对固定 Query $q$, 因果 Softmax 输出为
$$
o_t = \sum_{i=1}^t \alpha_{t,i} v_i, \qquad   \alpha_{t, i} = \frac{\exp(q^\top k_i)}{\sum_{l=1}^t \exp(q^\top k_l)} 
$$

最直接的线性化思路是: _假设所有 logits 都挤在均值附近 (没有谁特别突出), 对每个权重做一阶展开_

$$
a_{t, i} \approx \frac{1}{t} \left[1 + q^\top(k_i - \bar{k}_t)\right]
$$
 Step 1：中心化 logits
  定义 $s_i = q^\top k_i$，全部 $t$ 个 logits 的均值为 $\bar{s}_t = \frac{1}{t}\sum_{j=1}^t s_j$。
  令 $u_i = s_i - \bar{s}_t$，则 $s_i = \bar{s}_t + u_i$。
  关键性质：$\sum_j u_j = 0$（偏离均值的和恒为零）。

  Step 2：消去公共指数因子
  代入 Softmax：
$$a_{t,i} = \frac{\exp(\bar{s}_t + u_i)}{\sum_{j=1}^t \exp(\bar{s}_t + u_j)} = \frac{\exp(\bar{s}_t) \cdot \exp(u_i)}{\exp(\bar{s}_t)
  \cdot \sum_{j=1}^t \exp(u_j)} = \frac{\exp(u_i)}{\sum_{j=1}^t \exp(u_j)}$$
  公共因子 $\exp(\bar{s}_t)$ 消掉了，Softmax 只依赖偏离值 $u_i$。

  Step 3：一阶展开
  假设所有 logits 都挤在均值附近，即 $u_i \approx 0$。对 $\exp(u_i)$ 做一阶 Taylor：$\exp(u_i) \approx 1 + u_i$。
  代入：
$$a_{t,i} \approx \frac{1 + u_i}{\sum_{j=1}^t (1 + u_j)}$$

  Step 4：利用偏离和为零化简
  分母：
  $$\sum_{j=1}^t (1 + u_j) = t + \sum_{j=1}^t u_j = t + 0 = t$$
  所以：
  $$a_{t,i} \approx \frac{1 + u_i}{t} = \frac{1}{t}(1 + u_i)$$
  还原 $u_i = s_i - \bar{s}_t$，且 $\bar{s}_t = q^\top \bar{k}_t$：
  $$\boxed{a_{t,i} \approx \frac{1}{t}\left[1 + q^\top(k_i - \bar{k}_t)\right]}$$

  直观理解
  这个公式说：每个 token 的注意力权重 = 均匀分配 ($1/t$) + 一点线性修正 ($q^\top(k_i - \bar{k}_t)$)。高于均值 Key 的 token
  多得一点权重，低于的少吃一点。就是"先均分再微调"——和一阶线性化"假设没有赢家"的前提完全自洽。

即"均匀分配  $1/t$ 外加一点线性修正". 代入输出得到
$$
o_t \approx \bar{v}_t + \left[ \frac{1}{t} \sum_{i=1}^t v_i k_i^\top - \bar{v}_t \bar{k}_t^\top \right] q
$$

可以看作: 输出 = Value 的平均值 + 一个修正矩阵乘$q$ . 方括号里是 Key 和 Value 的互协方差型矩阵, 它记住的是"哪些 Key 方向伴随着哪些 Value 偏移".

  外积 $v_i (k_i - \bar{k}_t)^\top$ 展开看：

  $$\begin{pmatrix} v_{i,1} \\ v_{i,2} \\ \vdots \end{pmatrix} \begin{pmatrix} \tilde{k}_{i,1} & \tilde{k}_{i,2} & \cdots \end{pmatrix} =
  \begin{pmatrix}
  v_{i,1}\tilde{k}_{i,1} & v_{i,1}\tilde{k}_{i,2} & \cdots \\
  v_{i,2}\tilde{k}_{i,1} & v_{i,2}\tilde{k}_{i,2} & \cdots \\
  \vdots & \vdots & \ddots
  \end{pmatrix}$$


`好消息`是这个矩阵可以边看序列边累加, 用固定大小的状态维护, 复杂度线性. `坏消息`有三个, 而且都是根本性的:

1. 一阶权重可能为负, 已经不再是概率分布, §1.1 的凸组合与预算竞争性质全部丢失;
2. 指数竞争被压扁成线性响应: 当某个 Key 分数明显更高时, Softmax 会给它压倒性权重, 而线性式只能温和地多给一点, 表达不出"赢者通吃"的尖锐选择;
3.  $t^2$个权重被同时近似, 误差不是集中在某处, 而是均匀铺满整张注意力图.

这就是 Vanilla Linear Attention 的能力边界, 也是后续几步试图绕开的难题.

### 2.2 Softmax 本身存在精确的 Delta 递推

> 一句话总结: 不做任何近似, Softmax 的输出天然满足*"新输出 = 旧预测 + 步长 × 残差"* . Delta Rule 是 Softmax 自带的属性, 不是从外面强加的.

记分母$Z_t = \sum_{i=1}^t \exp(q^\top k_i)$ . 分母逐步累加 ($Z_t = Z_{t+1} + \exp (q^\top k_t)$), 输出因此可以写成精确递推

$$
o_t = \frac{Z_{t-1} o_{t-1} + \exp (q^\top k_t)v_t}{Z_t} = o_{t-1} + \alpha_{t,t}[v_t - o_{t-1}]
$$

式 6 可以解读为: 每来一个新 token, 输出就从旧预测  向新观测  挪一步, 步长是新 token 的自权重 . 这正是在线学习中最经典的 Delta Rule 更新. 注意, 此处零近似, 完全精确.

  Step 1：拆分分子分母
  $t$ 时刻的 Softmax 输出：
$$o_t = \frac{\sum_{i=1}^t \exp(q^\top k_i) \cdot v_i}{Z_t}, \quad Z_t = \sum_{i=1}^t \exp(q^\top k_i)$$
把最后一项从求和中拆出：
  $$Z_t = \underbrace{\sum_{i=1}^{t-1} \exp(q^\top k_i)}_{Z_{t-1}} + \exp(q^\top k_t)$$
$$\sum_{i=1}^t \exp(q^\top k_i) v_i = \underbrace{\sum_{i=1}^{t-1} \exp(q^\top k_i) v_i}_{Z_{t-1} \cdot o_{t-1}} + \exp(q^\top k_t)
  \cdot v_t$$

  ---
  Step 2：代入得到第一个等号
$$o_t = \frac{Z_{t-1} \cdot o_{t-1} + \exp(q^\top k_t) \cdot v_t}{Z_t} \quad \text{（第一个等号，精确）}$$

  ---
  Step 3：改写成凸组合

  令 $\alpha_{t,t} = \frac{\exp(q^\top k_t)}{Z_t}$（新 token 的自权重），其补足部分为 $1 - \alpha_{t,t} = \frac{Z_{t-1}}{Z_t}$。

  $$o_t = \underbrace{\frac{Z_{t-1}}{Z_t}}_{1-\alpha_{t,t}} \cdot o_{t-1} + \underbrace{\frac{\exp(q^\top k_t)}{Z_t}}_{\alpha_{t,t}} \cdot
   v_t$$
  即：
  $$o_t = (1 - \alpha_{t,t}) \cdot o_{t-1} + \alpha_{t,t} \cdot v_t$$
  ---
  Step 4：配成 Delta Rule 形式
  $$o_t = o_{t-1} - \alpha_{t,t} \cdot o_{t-1} + \alpha_{t,t} \cdot v_t$$
$$\boxed{o_t = o_{t-1} + \alpha_{t,t} \cdot (v_t - o_{t-1})}$$
那为什么不能直接用? 因为递推里的$o_{t-1}$  是"针对这个$q$ "的旧预测. 换一个 Query, 整条递推就得从头重跑; 序列里每个位置都有自己的 Query, 于是总代价是$1+2+\cdots+t = O(t^2)$ , 一分钱没省. 由此看清线性化的真正目标: 不是要删掉 Softmax, 而是要把 Query 从状态递推中分离出去, 让历史状态只由 Key 和 Value 累积, Query 最后来读一次即可.

## 3.2 固定状态的代价不是单一的近似误差

一句话总结: 固定状态的代价不是"精度差一点"这一件事, 而是四笔互相独立的账: 容量不够, 压缩时不知道将来要查什么, 尖锐选择变平滑, 以及长递推的数值风险.

_第一笔账是容量_. 状态  与序列长度无关, 但历史可以包含任意多的独立事实. 登记簿页数固定, 事实却可以无限多: 当独立关联数显著超过状态的有效自由度时, 多个 Key 必须共享状态方向, 相当于两条记录挤在同一页上. 如果 Key 相近而 Value 不同, 新写入会覆盖旧映射. Delta Rule 能更聪明地选择覆盖方向, 却不能创造无限容量.

_第二笔账更隐蔽, 来自 Query 无关压缩._ 状态在看到未来 Query 之前就已经决定了保留什么, 好比图书馆在读者到来之前就必须决定哪些书上架, 哪些书销毁. Full Attention 可以为每个新 Query 重新扫描全部 Key (所有书都留在库房, 随查随取), Linear Attention 只能查询事先压缩好的统计量. 对未来查询分布之外的 needle, 压缩器可能已经丢掉了唯一相关的 token. 这也是纯线性模型在精确复制, 多键关联检索和位置敏感回忆中容易落后的原因.

_第三笔账是尖锐性. Softmax 的指数竞争没有被完整保留_: Taylor 或有限特征映射只能在特定 logit 范围和分布上逼近指数核. 当少数分数需要以指数优势胜出时 (§1.1 说的"赢者通吃"), 有限维状态可能把尖锐选择变成平滑混合, 本该一家独大的注意力被摊成大锅饭. 若保留归一化分母状态 , 可以控制尺度, 但不能恢复被合并的 token 身份.

_第四笔账是数值稳定性, 来自递推转移的长程乘积._ 对 GDN,

历史信息经历  和一系列非正交 rank-1 变换. 门  是个两难旋钮: 太小会造成长期信息指数消失 (乘几百个 0.9 之后什么都不剩), 太接近  又会使状态干扰累积 (什么都不忘, 登记簿越来越挤). 即使每一步都稳定, 长乘积也可能产生方向性收缩和条件数恶化. 这要求 Key 归一化, 合理的门参数化, 以及分块时的对数域处理.

### 3.3.10 反例对混合架构的含义

一句话总结: 前面的反例打在四个不同的部位, 没有哪个单一技巧能同时堵住所有窟窿, 这正是"多数层用 Linear, 少数层留 Full"这种混合架构存在的理由.

先把反例整理一下, 它们分别作用在不同层面:

1. **压缩必丢信息**: 式 19 (零空间碰撞) 和式 23 (秩上限) 说的是固定特征压缩本身装不下任意历史;
    
2. **更新规则有偏差**: 式 24 (相近 Key 覆盖) 和式 25 (顺序不交换) 说的是 Delta 写入规则在特定输入上出错;
    
3. **遗忘无法两全**: 式 26 说的是衰减时间尺度的内在冲突;
    
4. **硬件效率的代价**: 式 30 说的是 KDA 为了内核速度牺牲的单步表达力.
    

它们不能由同一个技巧统一消除, 每个补救措施都是拆东墙补西墙: 增加状态维度会推迟零空间和秩反例出现的长度, 但固定维度最终仍被更长历史超过; 增加门控能改善数据分布上的保留决策, 但不能预知任意未来 Query; 增加 Delta 修正能降低无条件累积干扰, 却会在相关 Key 上产生覆盖; 使用通用 DPLR 可扩大单步转移集合, 又会付出更高的数值和内核成本.

看清这一点后, 少量 Full Attention 层的作用就不再是"工程上留个保险"那么简单了. 它们重新引入了逐 token 的 Query 条件化选择, 打断了"所有信息都必须挤过同一个固定状态瓶颈"的因子分解. 这相当于: 图书馆虽然大部分书按摘要归档了, 但每隔几层还是留了一个可以直接进原始库房翻书的通道. Kimi Linear 的 3 比 1 混合可以理解成: 让多数层接受压缩态射的归纳偏置 (省容量, 省带宽), 每隔若干层再提供一次不经过压缩瓶颈的 token 级区分能力 (兜住反例).

⚠️: 这里其实也暴露了一个问题, 基于Linear + Full的混合模式, 其KV-Cache的下界也被Full Attention的Size固定住了.

## 3.4 Linear Attention 的替代方案为何都不是免费午餐

一句话总结: 从 Vanilla 到 KDA 的每一次改进, 改的都是"怎么写, 怎么忘", 从来没有改变"登记簿页数固定"这个前提; 下表每一行的"主要代价"就是这个前提在不同设计下的具体表现.

|路径|保留的信息|主要收益|主要代价|
|---|---|---|---|
|Vanilla Linear|Key-Value 的低阶累计统计|结构最简单, 状态固定|无主动遗忘, 冲突持续累积|
|DeltaNet|当前 Key 方向的重构残差|可以覆盖旧关联|无时间遗忘, 过时关联仍长期存在|
|GDN|Delta 状态加标量寿命|稳定且可学习遗忘|整个 Key 通道共享同一衰减速率|
|通用 DPLR|对角衰减加独立低秩方向|表达力强|数值处理复杂, 分块矩阵乘更多|
|KDA|对角衰减加 Key 绑定的 rank-1 修正|细粒度遗忘与较高硬件效率|仍是固定状态, 且低秩方向受约束|
|Linear 与 Full 混合|压缩记忆加少量精确检索|缓解固定状态的检索上限|KV Cache 不再完全固定, 系统有两类内核|

这条演进路线说明, 每次改进都在有限状态内改变写入和遗忘规则, 而不是消除有限状态本身的容量约束.

## 4.2 KDA 的位置解释

一句话总结: KDA 不带位置编码 (NoPE) 却能感知位置, 因为一条信息从写入到被查询要穿过中间每一步的转移矩阵, 即离得越远, 穿过的矩阵越多, 这个连乘本身就是位置信号.

先看熟悉的参照物. RoPE 用正交旋转的累积编码相对位置:

含义: Query 和 Key 隔了多少个位置, 中间就叠多少个旋转矩阵 , 距离信息藏在"转了多少度"里. KDA 中, 历史从写入到被查询之间经历的则是形式完全平行的连乘

式 32 与 RoPE 对照解读, 差别有两点:

第一, RoPE 的  只由位置  决定, 是"死"的; 式 32 的每个因子由该位置的内容 (, , ) 决定, 所以这个乘积同时携带距离和内容信息. 它可以被看作一个数据依赖的乘法位置算子, 不只记"隔了多远", 还记"中间发生了什么".

第二, RoPE 的旋转是正交的, 只转方向不改长度 (保范数); KDA 的因子是非正交的, 允许选择性收缩. 可以让某些方向的信息在传递中主动变弱. 后者更灵活, 但也更容易遗忘和产生数值条件问题 (§3.2 第四笔账的具体来源).

所以 KDA 的 NoPE 设计不是简单地把位置编码删掉, 而是把位置归纳偏置交给了状态转移: 位置的活已经有人干了, 再叠一个 RoPE 反而多余. 4.4 的消融实验 (NoPE 长上下文优于 RoPE) 也支持这个解释.

## 4.3 WY 和 UT 如何把递推映射到 GPU

一句话总结: 递推天生是串行的, GPU 擅长的是大矩阵乘; WY 表示把一个块内的  步小更新打包成几个大矩阵, UT 变换解决打包时的先后依赖, 这是"数学重写换硬件效率"的典型操作.

先说清问题. GPU 的 Tensor Core 只在做大块 GEMM (矩阵乘) 时才能跑满; 而式 31 是一步一步的递推, 每步只做一次 rank-1 小修改, 就像让一条高速流水线每次只拧一颗螺丝, 硬件利用率极低. 解决思路是分块 (chunk): 把序列切成长度  (如 64) 的块, 块内的  个 rank-1 转移不逐个执行, 而是先在代数上合并成紧凑形式, 再用几次大 GEMM 一次算完.

##### WY 和 UT 是什么?

它们来自于 Householder 变换, 名字都来自原始论文中的矩阵记号.

Householder 变换是形如  的矩阵, 几何上是沿方向  的镜面反射, 是 QR 分解的标准构件. 注意 KDA 每步的擦除项  正是这个形状 (KDA 论文原文称之为广义 Householder 变换), 所以数值线性代数积累了几十年的加速技巧可以直接搬过来.

首先从性能上来看, 虽然RULER@128K 和 MRCR@128K 的性能上看上去 KDA 是最好的, 例如MRCR (multi-round co-reference resolution) 要求在长上下文中区分多个高度相似的干扰项并追踪指代, 干扰项彼此相近, 正是 §3.3.5 "相近 Key 覆盖"的压力形态. KDA 的逐通道遗忘在这里拉开了与标量遗忘 (GDN-H 23.9) 和纯 Full (MLA 22.6) 的差距, 说明细粒度时间尺度确实帮助了"该记的记住, 该清的清掉".

但是, 我们注意到实际上MRCR还是在一个很低的分数区间, 无非是一个"矮子里的将军". 而在LongBench 这类恰好偏多跳与跨文档推理, 即需要把多个远距离证据串起来的任务. 与 §3.2 第二笔账一致: 压缩状态在"未来才知道要串哪几条证据"的场景下最吃亏.

其实整个论文评测还是缺乏一些500K和1M级别的数据的. 这里从理论框架上进行一个推测:

1. **KDA 层的远距记忆在 512k 尺度上近乎必然湮灭.** 按 §3.3.7 的遗忘账, 一条写入后不再被访问的记忆经过  步只剩 ; 即使每步  (已经非常接近不遗忘),  时保留比例约 . 除非门学会对特定通道长期锁定  (代价是该通道从此不可清理, §3.3.7 的两难), 否则跨 512k 的 needle 检索几乎完全依赖那四分之一的 MLA 层.
    
2. **MLA 层自身在 1M 尺度承受压力.** 当然在1M context下, 即便是Full Attention也有问题, 在 §1.4 的注意力摊薄: 权重上界按  收缩, 从 128k 到 1M 竞争者多 8 倍, 想保持同样尖锐的选择, logit 间隔需要再增长约 ; 而模型只在 128k 量级的激活数据上训练过, 这个间隔增长没有训练信号来源.
    
3. **状态容量密度单调恶化.** 每头状态固定 , 从 128k 到 1M, 每个状态元素平均要承载的 token 数增加 8 倍, §3.3.2/3.3.4 的碰撞论证随  单调增强. 预计退化最快的正是 MRCR 型多针任务, 即多个相似实体挤进同一状态子空间是 §3.3.5 覆盖偏差的高发区, 而该任务在 128k 时绝对分已经只有 29.6.
    
4. **层级反转趋势的延长线.** 前表显示 GDN-H 在 128k 已跌到 MLA 之后, 即"上下文越长, Full 层相对价值越高". 若该趋势在 512k–1M 继续, Kimi Linear 相对 MLA 的质量领先在检索重型任务上可能收窄甚至局部反转, 当前领先 (RULER +3.0, 平均 +2.3) 并没有大到能吸收一次趋势外推.
    

## 4.5 KDA 没有解决的问题

一句话总结: KDA 把"怎么忘"做到了目前的工程上限, 但 §3.3 列出的结构性上限: `容量, Query 无关压缩, 表达力约束`一个都没消失; 现有实验也还不足以下最终结论.

逐条对账.

1. _容量上限还在_: KDA 仍把任意长度的历史压入  个状态元素. 对角门提高的是状态的时间尺度分辨率 (旋钮更多了), 不是容量 (登记簿没变厚). 精确检索, token 身份恢复和未来未知 Query 的选择性仍然受 §3.3.1–3.3.4 的理论上限约束. Kimi Linear 采用 3 比 1 的 KDA 与 MLA 层间混合, 正是承认了这一点后的架构性补救.
    
2. _表达力约束还在_: 受约束 DPLR 不是通用 DPLR 的无损重参数化. 独立的  和  可以表示非对称的删除与写入方向, KDA 则要求它们由同一个 Key 派生 (§3.3.9 的反例给出了单步不可表示的具体例子). 该约束换来了 4.3 的内核速度, 但在需要不同读写子空间的任务上可能限制表达力. 这是一笔用表达力换速度的交易, 不是免费优化.
    
3. _数值风险还在_: 非正交位置乘积 (式 32) 可能产生过度衰减. L2Norm 能控制  的谱尺度, 却不能保证长乘积像 RoPE 一样保范数; 对角门的通道饱和 (某些  长期贴着 0 或 1) 还会造成梯度消失或近乎不遗忘. 这些问题需要训练规模, 长度外推和低精度实验共同检验.

## 5.3 静态稀疏通过图结构换取可预测访问

一句话总结: 静态稀疏不看内容, 按位置划死名单. 挑名单 (topk 计算) 的成本为零, 内存访问完全可预测, 赌的是"预设的连接模式恰好覆盖任务需要的依赖". 典型代表就是滑动窗口注意力 (SWA) 机制.

最简单的静态模式是滑动窗口: 每个 Query 只看最近  个 token,

计算量从  降到 . 它的内存地址连续, 可直接形成规则块, 对 GPU 极其友好. 代价是单层感受野只有 : 一条远程依赖想被看到, 只能靠层层接力. 第一层把信息传  步, 第二层再传  步, 经过  层最远约传播  个位置 (若没有全局 token 或扩张连接). 这不是单层的全局检索, 而是沿稀疏图逐层传递, 像消息在邻居间一站站转发; 传得到, 但每一站都可能失真.

BigBird 型模式在窗口之外增加少量全局点 (所有人都能看它, 它能看所有人, 相当于枢纽机场) 和随机边 (随机抽几条远程连线), 扩大图直径并提高连通性; 扩张窗口则让远距边按固定步长出现. 这些方法的共同数学基础是设计一个稀疏有向图: 局部边负责高频邻域, 少量长边负责把任意两点间的路径长度压短.

它们的优点和缺点是同一枚硬币两面: 支持集选择成本几乎为零 (名单是死的, 不用算), 但模式与内容无关, 若任务的关键依赖恰好不在预设拓扑上 (比如答案藏在一个既非邻居, 又非全局点, 又没被随机边抽中的位置), 静态图无论多少层都可能传不到位.

### 5.4.2 HiLS: 把"选得准"从模仿升级为端到端学习

一句话总结: HiLS-Attention (Tencent HY) 把块稀疏选不准的问题拆成两个根因: _摘要表达力弱, 选择不可学习_. 并分别给出了数学上有出处的解法; 它的意义在于把稀疏注意力的目标从"逼近全注意力"翻转为"可以超越全注意力".

两个发现值得注意: 端到端学到的检索分配优于按真实注意力质量的分配; 全注意力的检索能力会被继续训练侵蚀, 而稀疏架构把它固化为结构属性. 稀疏由此从"对稠密的妥协"变成了"有独立价值的归纳偏置".

### 5.4.3 IndexCache: 把"挑得便宜"做到跨层

一句话总结: 核心注意力稀疏化之后, 索引器成了新的主矛盾. IndexCache (Tsinghua/Z.ai) 发现相邻层的 top-k 名单重合 70%–100%, 于是让多数层直接抄少数层的作业, 砍掉 75% 的索引计算而质量几乎不变.

先看瓶颈有多真实: 对 30B DSA 模型的 profiling 显示, 200K 上下文 prefill 阶段索引器占总延迟的 **81%**, decode 阶段也占 41%. 这是 Amdahl 定律在架构层的生动演绎: 优化掉主矛盾 (注意力 ) 之后, 原本次要的部分 (每层一个  索引器,  层共 ) 升级为新主矛盾.

方案的机制简单到一句话: 把  层划分为 F/S 两类, F 层正常计算索引并缓存名单, S 层不设索引器, 直接继承最近前置 F 层的名单. 核心注意力  完全不动, 推理侧改动只是一个条件分支. 零额外显存, 零新 kernel. 难点全在"留哪些层":

- **免训练路线**: 从全 F 出发贪心搜索, 每步试探翻转一层为 S, 以校准集 LM 损失为唯一判据. 这里藏着一个高价值的负结果: 用索引重叠率, 输出余弦相似度这类局部指标做判据 (即使配全局最优的动态规划) 必然失败. 误差的伤害发生在跨层传播的级联中, 只有端到端指标能看见. 教训可迁移: 评价指标必须与最终目标对齐, 优化聪明的替代品不如直接优化你在乎的东西.
    
- **训练路线**: 把 DSA 的单层蒸馏推广为多层蒸馏 (让保留的索引器同时对齐它服务的所有层的注意力分布), 可证明其梯度等价于朝多层分布的质心蒸馏. 训练后模式敏感性完全消失, 均匀间隔保留即可. 1/2 保留率甚至反超全索引器基线. 这说明结构敏感性是训练的产物, 不是模型的宿命.
    

实测: 30B 模型砍掉 75% 索引器, 200K prefill 加速 1.82 倍, decode 加速 1.48 倍, 质量损失可忽略; 在 744B 的 GLM-5 上以 50% 削减取得约 1.2–1.3 倍端到端加速, 已进入生产部署.

## 5.5 压缩注意力: DeepSeek-V4 把稀疏建立在有损压缩之上

一句话总结: CSA/HCA 不是"选哪些原始 token", 而是"先把 token 压成块摘要, 再决定读哪些摘要". 它把 Sparse 的支持集近似和 Linear 的有损压缩嫁接在了一起. 这是介于两种契约之间的第三条工程路线.

### 5.5.1 机制: 两级压缩率加一个滑动窗口

DeepSeek-V4 在层间交替使用两种注意力:

**CSA (压缩稀疏注意力)** 先把每  个 token 的 KV 压成一个条目. 压缩不是简单平均, 而是用可学习的门控权重做块内 Softmax 加权:

其中  是 KV 投影,  是压缩打分,  是块内可学习位置偏置; 相邻块之间还做半窗重叠以缓和边界断裂. 然后一个低秩 FP4 索引器在这  个压缩条目上打分, 每个 Query 只选 top- 个条目进入精确注意力 (共享 KV 的 MQA, 压缩条目同时当 Key 和 Value).

**HCA (重度压缩注意力)** 用激进得多的压缩率  (不重叠), 但在压缩条目上做稠密注意力. 候选只剩  个, 干脆全看, 不再需要索引器.

两者都附带一个  的滑动窗口分支保留最近 token 的未压缩 KV, 并使用可学习 sink logit (§1.4) 允许注意力总和小于 1. 层间按约 1:1 交替排布 CSA 和 HCA.

用 §5.4 结尾 NSA 的语言来读: NSA 把压缩分支, 选择分支, 滑动分支并列在同一层内; DeepSeek-V4 则把三种分辨率拆到不同尺度上. SWA 是高分辨率局部视野, CSA 是中分辨率稀疏骨架 ( 压缩加 top-), HCA 是低分辨率全局概览 ( 稠密). 并沿深度交替, 让相邻层互补对方的盲区.

### 5.5.2 数学定位: 在商空间上求解同一个 EOT 问题

压缩注意力可以精确地放进本章的框架. §5.1 说 Sparse 是把单纯形  缩成一个面 (删掉部分坐标轴); 压缩注意力则先做一步商映射: 把  个 token 的坐标轴合并成一根, 得到低维单纯形 , 再在其上求解同一个熵正则问题 (HCA 用完整低维单纯形, CSA 再叠加 §5.1 的面约束). 关键差别在于合并的方式: 块内分配比例  由压缩权重在**看到 Query 之前**预先决定, Query 只能调整"给这个块多少总预算", 不能调整"块内怎么分".

这正是 §3.2 第二笔账 (Query 无关压缩) 的稀疏版本. 于是误差从 §5.2 的单一  变成了两项:

第一项仍由索引器召回控制 (式 41 的间隔分析原样适用, 只是打分对象换成了压缩条目); 第二项是新的, 不可由读取端修复. 块内某个 needle token 若在压缩时只分到很小的 , 之后无论 Query 多尖锐都放大不回来. 这与 §3.3.1 "碰撞后无法用读取函数恢复"是同一性质的限制, 只是碰撞半径被限制在块内 ( 个 token), 而非 Linear 的整段历史. SWA 分支的作用由此清晰: 它专门兜住"needle 恰好在最近 128 个 token 里"这种压缩最容易伤到的情形.

因此三种机制形成一个连续的压缩谱系: Full (不压缩) → CSA ( 有损压缩 + 稀疏选择) → HCA ( 有损压缩 + 稠密读取) → Linear (全历史压进固定状态). 压缩率越高, 容量和带宽越省, Query 无关损失越大. 不存在跳出这个谱系的免费选项.

### 5.5.3 工程收益

这套设计同时削减了两项成本. KV 容量方面, CSA 层每 token 约  B (压缩 KV 加 FP4 索引缓存), HCA 层每 token 约  B, 加上每层固定的 128-token 窗口; DeepSeek-V4-Pro 全模型在 1M 上下文的 KV Cache 约为 V3.2 (DSA) 的 10%, 约为 BF16 GQA8 基线的 2%. 计算方面, CSA 层的索引扫描为每 token  FLOPs, 约为 V3.2 DSA 全 token 扫描 () 的四分之一; 全模型 FLOPs 在 1M 上下文约为 V3.2 的 27%, 且随长度增长的斜率明显更缓. 值得注意的是短序列的反例: 8K 上下文时 V4-Pro 的每 token FLOPs 反而高于 V3.2 (0.84 倍加速比), 因为压缩器, 索引器和分组输出投影的固定开销在短上下文摊不薄. 这再次印证: 稀疏化的收益是长度的函数, 不是无条件的.

### 5.5.4 压缩注意力没有解决的问题

CSA/HCA 缓解了 token 级路由的两大痛点 (索引二次项常数, 随机 gather), 但有三点边界要读准. 第一, 压缩缓存仍随  线性增长, 只是斜率除以 . 超长流式场景下, 容量优势最终仍属于 Linear 的固定状态. 第二, 块内混合权重是 Query 无关的, §3.3 的碰撞判据在块内原样成立, 只是被  封顶;  的 HCA 在压缩时会把细粒度结构大量填平, 只保留宏观块间关系. 第三, 该架构尚无与 KDA 混合, NSA, MoBA 在同模型同数据下的对照, 其质量结论 (基准持平 Claude 级模型) 与结构选择 (1:1 CSA/HCA 交替) 之间的因果关系还不能分离. 与 §4.4 对 Kimi Linear 消融的读法一样, 这些数字支持"该设计在该规模下可行", 不支持"该设计普遍最优".

# 6. 内存访问模型与并行性

前五章在数学层面比较了 Full / Sparse / Linear 三种 Attention. 本章把它们搬上真实的 GPU. 在硬件视角下, 决定性能差异的不是 FLOPs 总量, 而是三个微架构层面的事实.

1. _算力与带宽严重失衡_: 现代加速器的 BF16 Tensor Core 峰值与 HBM 带宽之比, 即 roofline 的脊点, 在 300 FLOPs/Byte 量级. 算术强度低于这个数的 kernel, 都在等内存.
    
2. _存储层次构成一个陡峭的容量阶梯_: 寄存器堆 (每 SM 约 256 KB), 共享内存 (每 SM 约 228 KB), L2 (几十到一百多 MB), HBM (百 GB 级). 数据落在哪一层, 可用带宽就差一到两个数量级.
    
3. _SIMT 执行模型天然偏好规则性_: 访存要合并对齐, 大块搬运要走异步拷贝/TMA, 矩阵乘要凑齐 Tensor Core 的 tile 形状. 任何不规则的访问, 代价就是占用率下降或算力浪费.
    

此外还有一道来自 HBM 容量的硬约束: 注意力 KV Cache 占多少字节, 直接制约可并发的请求数; 对于KVCache的处理复杂度和存储容量需求以及前缀复用的能力不光需要站在单机的视角进行考虑, 还需要考虑全局的 MaaS 平台的工程复杂度.

## 6.1 三类Attention机制的KVCache容量和Decode带宽

一句话总结: decode 阶段三种机制的算术强度全是个位数 FLOPs/Byte, 一律深陷 roofline 的Memory bound 区域. 这里争的从来不是谁算得快, 而是谁读的字节少; 容量则通过限制并发 batch 间接决定吞吐.

以 H100/B200 量级的加速器为参照: BF16 Dense算力约 1 到 2.2 PFLOPS, HBM 带宽约 3.3 到 8 TB/s, 两者之比给出 roofline 脊点约 280 到 300 FLOPs/Byte; L2 容量 50 到 126 MB, 带宽约为 HBM 的数倍; 共享内存每 SM 约 228 KB, 寄存器堆每 SM 256 KB. 整个判据简化为一个除法: kernel 的算术强度  FLOPs  HBM 字节,  低于脊点则带宽决定延迟, Tensor Core 空转; 高于脊点才轮到算力说话.

## 6.2 Sparse 的不规则访问为何可能吞掉 FLOPs 收益

一句话总结: "少读 98% 的 KV"在纸面上是 50 倍加速, 但 gather 在微架构的每一层都有代价: 合并率不足, 依赖延迟, 预取失效, 负载不均, 每一层都在往回扣. 块级化和索引 L2 驻留, 是仅有的两张挽回牌.

**第一层账: DRAM 与合并访存.** GPU 的全局访存以 warp 为单位合并: 32 个线程的请求若落在少数几个 128B 扇区内, 一次事务即可搞定; 而 top-k 选出的 token 地址随机散布时, 一个 warp 可能触碰 32 条不同的 cache line, 事务数急剧放大, 每次传输的有效字节占比骤降. 再深一层看 DRAM 自身的行为: HBM 以行缓冲 (row buffer) 为单位工作, 顺序流式读能持续命中已激活的行, 随机 gather 则频繁触发行激活/预充电, 有效带宽可以掉到峰值的三成以下. 换言之, 同样是"读  字节", 散着读和连着读的真实成本差数倍: 式 (43) 第二项的系数从来不是一个常数.

**第二层账: 依赖 load 链与延迟隐藏.** gather 的地址来自 top-k 的输出, 这是一条数据相关链: 先算完索引分数, 再排序选出下标, 再按下标发起 KV load. 硬件预取器对这种间接寻址无能为力, TMA/异步拷贝也需要在发起时就知道地址. SIMT 靠海量 in-flight 请求隐藏几百个周期的 HBM 延迟, 而依赖链把"能够提前发射的请求窗口"压窄了. 唯一的补救是软件流水: 把索引和 gather 拆成两个流水阶段, 用双缓冲让第  块的 gather 与第  块的打分重叠. 但代价是共享内存占用翻倍, 挤压占用率 (occupancy), 反过来又削弱了延迟隐藏能力: 这是个真实存在的三角权衡.

**第三层账: 分支与负载不均.** 不同 Query 的 top-k 集合不同, 同一 CTA 内的 Query 虽然处理的 KV 列表长度相同 (都是 ), 但位置各异, 导致共享内存复用失效: 每个 Query 各拉各的 KV; 跨 CTA 看, 支持集的重叠度决定了 L2 的二次命中率. 极端情况下, 每个 Query 的 gather 都是全新地址, L2 形同虚设.

**块级稀疏, 是对前三层账的一揽子回应.** 一次选中连续  个 token 之后: 地址天然合并 (第一层), 块基址一旦确定即可用 TMA 发起大块异步搬运 (第二层), K/V tile 形状规整可直接喂 Tensor Core 的 MMA 指令 (计算侧). 代价是块越大, 无效 token 越多, 有效稀疏率被稀释. 因此 token 级精度与块级硬件效率之间, 存在一道真实的 Pareto 前沿, 不是单靠内核优化就能填平的. NSA 与 HiLS (§5.4.2) 的打包 kernel 选用  量级, 并让相邻 Query 共享块并集, 正是在这条前沿上找的平衡点; HiLS 实测相邻 Query 块重叠率超过 80%, 说明第三层账里的 L2 二次命中大部分确实能兑现.

## 6.3 Linear 状态矩阵会不会成为局部热点

一句话总结: 会成为带宽热点, 不会成为争用热点. 真正的微架构问题是: 状态该驻留在存储层次结构的哪一层? 以及递推依赖  砍掉了 GPU 赖以为生的一个并行维度.

先扫清一个常见误解: 状态矩阵不是共享变量. 同一序列同一头的  只由下一步使用, 不同序列和不同头各自拥有独立状态, 可以按 batch, head 和  tile 分片, 不需要原子操作, 不存在多 CTA 竞争同一地址引起的 L2 slice 排队或原子序列化. 恰恰相反, 它的访问模式是硬件最喜欢的一种: 地址固定, 布局连续, 每步重复触碰, 时间局部性远好于那些只读一遍就丢的长 KV 流.

**第一层问题: 状态驻留在内存层次结构的哪一层.** 同样的问题, 状态矩阵如何提高L2 Cache HitRate, 如何尽量的在SMEM处理? 针对未来更长的Context需求, 状态矩阵势必无法记录历史也需要一定程度上扩大维度. 例如当前单头 32 KiB 恰好卡在"片上放得下, 但放不下几个"的尴尬区间, batch × head × layer 的完整工作集必然溢出 L2. 若每个 token 单独 launch recurrent kernel, 每层状态都要 HBM 读入写回 (单头 FP16 至少 64 KiB 往返, 未计中间量), 再加上每层每 token 一次 kernel launch 的固定开销 (微秒级, 与毫秒级 TPOT 相比不可忽略, 61 层每 token 就是 61 次).

**第二层问题: 依赖链砍掉一个并行维度.** 递推在硬件上的含义, 要放到 GPU 的并行度清单里来看.

Full Attention decode 拥有四个可并行维度: `batch`, `head`, `KV 长度方向的 tile` , 以及 `Verification 时的多 Query`.

Linear recurrent 只剩三个: `batch`, `head`, `状态矩阵内部的 tile`; 时间步方向被  严格串行化, 而 split-K 那个随  增长的维度天然不存在 (这本是好事, 没有  方向的工作要赶), 但`多 Query 并行`也一并失去了. 并行度不足在微架构上的直接后果就是占用率不足: 一个 B200 有约 150 个 SM, 每个都需要多个常驻 warp 才能隐藏延迟; 当 batch × head 的乘积小于几百时, SM 大面积闲置, 此时 Linear 的每 token 延迟由"串行链上的一次状态更新"的裸延迟决定, 而不是带宽. batch 足够大时跨序列并行足以掩盖这一切; 但 batch 小的时候, 或`投机 Verification` 一次要走  个连续 token 时, 序列内临界路径就暴露出来了.

当然这些与Linear Attention Kernel实现也有一定的关系. 例如使用 chunkwise WY/UT (§4.3) 在代数上把  个 rank-1 转移打包成Dense GEMM: 块内工作变成  级 GEMM, Tensor Core 可以充分使用, 状态只在块间边界读写一次. 但对很短的块 ( 小于为  优化的块长), padding 开销可能反噬并行收益, 例如投机解码过程中的 Verification Kernel 问题的根源.

## 6.4 KV Cache 容量与并发: Prefill, Decode 与 Prefix 复用的平台账

一句话总结: §6.1–§6.3 算的是单请求的带宽与驻留, 本节把视角抬到服务平台: 真正决定盈利能力的是, 一块 HBM 能同时容纳多少请求, 以及前缀复用能省掉多少重复 prefill.

在这本账里, token 索引缓存 (含压缩 Sparse) 与递归状态缓存是两种性质不同的资产:

- Sparse Attention的KVCache写后只读, 可任意切分, 全平台共享一份;
    
- Linear Attention是每请求私有的状态, 复用只能靠稀疏对齐的全量快照加快照间重放.
    

而对于MaaS平台最典型的"短前缀高共享"负载, 天然站在 Sparse Attention 这一边. 另外还需要考虑一个国内的现状, 我们由于算力非常有限, 其实平台方会更加看重KVCache的命中率, 利用存储空间换算力.

##### Prefill实现

_Sparse Attention prefill 是 append-only_: 每 token 的 KV 写入新页, 写后只读, 页边界对齐, TMA 大块搬运友好. V4 多一道压缩器流水线: 每攒满  个 token 产出一条压缩条目, 未满块的尾巴连同 hidden state 驻留 FP32 临时 buffer (每层数十 KB), 页与前缀边界须对齐到  块粒度, 这是内核与缓存布局协同设计的结果.

_KDA 路线的 prefill 则是 chunkwise 压缩写_: chunk () 并行算法把整段 token 的转移合并计算, chunk 中间状态只是 workspace, 默认不持久化; 最终只把 segment 末尾的完整状态与末尾  个卷积输入写回本请求的 state slot. 只有平台要求 prefix 追踪时, 才在对齐的 cache chunk 边界额外输出全量状态快照

##### Decode实现

_Sparse Attention decode 每 token 追加  字节新条目_, 再按 top-k gather 选中条目 (CSA 按压缩块连续 gather); 多个并发请求读同一共享前缀页时, 容量上只有一份, 读流量还能被 L2 合并.

_KDA 的 decode 围绕 request-level slot_: 每 token 从 HBM 读出完整状态, 原地 low-rank 更新后写回, 每请求每 token 至少  的往返流量; 状态私有,  个并发就是  份, 无任何共享摊薄. ReplaySSM 类 ring 用 compact update factors 延迟完整矩阵的写回, 降的是这笔带宽, 不改变容量的  性质.

投机解码把两者的缓存语义差异放到最大: Sparse Attention路线只需为草稿 token 追加条目, 拒绝即页表截断, 零额外容量; KDA 则必须能恢复到接受前缀 : 朴素实现要为每个草稿步保存一份完整中间状态, 每请求临时内存  ( 时 48 层对照约 +200 MiB, 是活跃状态本身的 4 倍; 对照压缩 Sparse 的  KiB  KB, 差四个数量级).

##### Prefix 复用

大型Maas平台的效率很大程度上来自前缀复用: 系统提示, 工具描述, 多轮历史, 都是海量请求共享的前缀.

Sparse Attention在这里有四个一气呵成的性质:

- 条目不可变, radix 树引用计数共享, 全平台物理存一份;
    
- 任意 token 边界可切分, 命中即跳过整段 prefill;
    
- 冷前缀可分层 offload. V4 的 disk context cache 把所有压缩条目落盘, 命中时读回到最后一个完整压缩块, 块尾不满的 token 重算;
    
- 体积约 8 倍于压缩条目的 SWA 条目则提供三档磁盘策略: 全存, 周期检查点 (每  个 token 存最后  条, 命中后重算尾部), 零缓存 (借压缩条目重算最后  个 token).
    

这种方法在复用时计算和容量两条账同时省.

KDA 的前缀复用是另一套机制:

- 前缀的可复用形态只有前缀末尾的全层状态快照, 单价 , 与前缀长度无关;
    
- 状态不能在任意 token 位置切分, radix 分裂产生的新中间节点只是状态 tombstone, 分支点没有现成快照时, 只能从最近的前序快照重放  个 token;
    
- 命中也不是引用计数, 而是 copy-on-restore: 快照实体拷贝进新请求的私有 slot,  个并发请求共享同一前缀, 仍需  份完整活跃状态.
    

混合架构里只有 KDA 层需要这套机制, 其 MLA 层仍按 token 索引正常共享前缀.

一句话概括: Sparse 的前缀复用是容量复用加计算复用, Linear 的前缀复用只是计算复用. 个人的评估是 Linear Attention带来的工程复杂度会更高.

## 6.5 考虑投机解码

通常对于一个模型而言, Decode的性能直接关系到模型的营收. 通常为了提高Decode效率和用户体感都会采用投机解码的机制. 但是正如前面所述, 即便我们采用DSpark / Dflash 一类的并行解码机制, 有更高的 gamma. 但是在验证阶段, Linear Attention 相对于Sparse Attention的耗时是需要仔细核算的, 对于生成的Draft token, 在通过Linear Attention验证时, 对于状态矩阵的顺序依赖, 是否会占用更多的内存, 从而在本来一个Memory bound的 Decoding计算中增加更多的访存, 使得整体的投机解码带来的性能收益由于验证资源消耗而存在明显的上界?

# 7. 一些总结

本文从算法和Infra层面详细分析了 Sparse Attention 和 Linear Attention. 在近似误差上, Linear Attention 如果未来需要承载更长的Context, 很有可能需要进一步扩大状态矩阵的规模, 那么Attention的算力消耗或者说整体来看模型的激活参数规模也会相应的扩大很多.

另一方面正如前面分析所述, 从推理Infra的角度来看, 实际上有很多实现的细节, 基于Linear Attention的 KVCache的工程复杂度和Decoding阶段的显存占用以及对投机解码的性能收益的影响可能也需要更详细的评估.

回到本文一开始的话题, 对于Kimi K3基于KDA的最终效果, 收益来自于`数据质量`, `参数规模`还是`模型结构`, 这一点确实很难评估.

另一方面对于Linear Attention的价值, 或许还需要做更多的实验, 例如在一个Full Attention的模型上, 按照模型层数做TDA, 是否存在就近的几层相对Attention的变化较小的情况, 特别是从TDA的 Persistent Homology来看, 这样恰好使得Linear Attention的简化计算存在收益?

最后, 我们还没有看到基于Linear + Sparse 的Hybrid 模型的出现.  Linear + Full Attention实质上还受到Hybrid 比例和Full Attention 对KVCache的显著占用而导致的资源消耗下界的影响...
