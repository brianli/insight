## Agentic RL 正在改变大模型的训练方式

随着大模型能力不断提升，行业关注的重点正在从“模型能不能回答问题”，逐渐转向“模型能不能真正完成任务”。一个能力足够强的 Agent，不仅要理解用户需求，还要能够自主规划步骤、调用工具、运行代码、操作软件，并在执行失败后发现问题、调整策略。可以说，Agent 能力正在成为衡量下一代大模型实用价值的重要标准之一。

而要让大模型真正具备这些能力，仅靠阅读文本和模仿答案已经不够，它还需要在真实或模拟环境中不断完成任务，在一次次尝试中积累经验。这就是面向 Agent 的强化学习（Agentic RL）：系统不断给 Agent 布置任务，例如编写并运行代码、操作软件、搜索整理信息等；Agent 自主规划步骤、调用工具并完成任务；系统再根据任务是否成功、过程是否合理给予反馈，并通过强化学习更新大模型的权重。经过成千上万甚至数百万次训练，模型便能逐渐掌握更可靠的规划、决策和工具使用能力，从“会回答问题”真正走向“会完成任务”。

## Agentic RL 需要新的基础设施

与传统强化学习不同，Agentic RL 已经不再是在一个 Python 函数或静态模拟器中计算奖励。今天的 Coding Agent、Computer-use Agent 和通用任务 Agent，需要在真实的软件环境中读取代码、修改文件、安装依赖、启动服务，并与数据库或外部系统交互。这意味着，每一次训练都需要一个真实、完整且独立的执行环境。

支撑这类环境的基础设施，需要做到强隔离、可扩展和高效率：为每个 Agent 提供独立的安全边界，避免影响宿主机和其他训练任务；横向扩展并发运行规模，并高效管理持续增长的镜像和环境模板；以可接受的成本支撑数千乃至数万个环境并发运行。

我们在研究中发现，在奖励驱动下，Agent 可能尝试突破执行边界、访问隐藏服务、修改评测逻辑，甚至读取外部答案。这些行为虽然可能获得更高奖励，却会破坏训练信号，因此强隔离是可靠 Agentic RL 的基础。

传统的沙盒通常只提供安全隔离的执行空间，并不足以支撑智能体完成多样的任务。智能体执行不同的任务依赖特定的操作系统、语言运行时、编译器、软件包、工具链、代码仓库和外部服务，这些依赖需要通过镜像和环境模板提前准备。随着任务数量的增长，所需环境会迅速形成规模庞大、差异显著的镜像集合，其总量甚至远超单个节点的存储容量。因此，智能体运行环境不仅要解决隔离问题，还必须具备可扩展到海量镜像的能力。

另一方面，一个典型的 Agentic RL 任务往往需要同时维护数千个有状态环境。它们在等待模型生成下一步动作时大多处于空闲状态，但如果每个环境始终独占 CPU、内存和存储资源，环境成本很快就会成为训练规模继续扩展的瓶颈。传统虚拟机很难兼顾隔离性、真实性和资源效率，这也催生了对新一代 Agent 执行环境的需求。

## 今天，我们正式开源 AgentENV

为了解决上述问题，我们正式开源面向大规模 Agentic RL 的 Agent 执行环境基础设施平台——**AgentENV** **（AENV）**。

AgentENV 基于 Firecracker 构建强隔离的微虚拟机执行环境，并通过镜像按需加载、增量快照、写时复制 Fork、内存与存储复用，以及弹性生命周期管理，为每个 Agent 任务提供安全、可扩展且可快速复制的执行环境。它既能保证不同 Agent 之间互不干扰，又能以更高的部署密度和更低的资源成本支撑大规模 Agentic RL。

在实际部署中，AgentENV 的并发承载能力与节点物理规格及微虚拟机资源配额相关。在典型配置下（如 128 核 512GB 内存的服务器），单节点实测可稳定运行 400 个并发 Agent 执行环境（典型规格：2 vCPU / 4 GB、4 vCPU / 8 GB），集群在生产实践中已成功验证可扩展至 30,000 个 Agent 执行环境，且理论上可按节点规模继续线性扩展。基于模板的启动或恢复延迟低至 49 ms，快照创建延迟低至 133 ms；在并发扇出场景下，每个可立即执行的子环境摊销 Fork 延迟低至 122 ms。与现有方案相比，AgentENV 可将环境生命周期管理开销降低约一个数量级。

这意味着，Agentic RL 中原本耗时且昂贵的“创建环境—执行任务—保存状态—恢复或复制环境”过程，可以在更短时间内完成，并以更大的规模并行运行。研究者和开发者能够将更多计算资源投入模型训练本身，而不是消耗在环境管理上。

目前，AgentENV 已被用于 Kimi K3 等多款先进模型的强化学习训练。今天，我们将这套支撑大规模 Agentic RL 的基础设施正式开放，希望帮助更多团队降低 Agentic RL 的门槛，也期待与社区一起探索下一代 Agent 的训练范式。

## AgentENV 的核心设计

围绕 Agentic RL 对**强隔离、****可扩展、****高效率**的要求，AgentENV 从环境管理、资源复用到状态管理进行了重新设计，让大规模 Agent 训练真正具备可扩展性。

### 跨节点扩展异构环境

AgentENV 可以在多台服务器上大规模运行 Firecracker 微虚拟机，并兼容 OCI 镜像生态。镜像通过 OverlayBD 从远程对象存储或远程文件系统按需加载，本地磁盘仅作为容量有限的热数据缓存。

因此，集群可使用的镜像和环境模板总量可以超过单节点磁盘容量，也不需要将所有镜像提前预热到每台主机。这对于包含大量代码仓库、依赖版本和工具链的 Agent 训练尤为重要。

### 让空闲环境变得便宜

AgentENV 支持在数十毫秒内启动或恢复基于快照的环境，并在百毫秒量级完成暂停。环境等待模型推理时，可以释放 CPU 和可回收内存；新动作到达后，再从已有状态快速恢复。

训练系统由此不必为所有在逻辑上存在的环境持续保留完整物理资源，从而能够以更低成本维持数千个有状态执行环境。

### 原生支持增量快照与 Fork

AgentENV 增量记录内存和文件系统变化，无需在每次保存时复制完整虚拟机。快照可以持久化到兼容 S3 的对象存储或共享分布式文件系统，避免节点故障导致状态丢失。

同一个中间状态还可以通过写时复制 Fork 为多个独立执行环境，让 Agent 并行尝试不同的工具调用、代码修改或操作序列。这为多轨迹采样、树搜索和反事实探索提供了高效的环境基础。

### 长时间维持高密度

随着微虚拟机持续运行，不同环境会逐渐产生更多私有状态。AgentENV 通过存储和内存的持续复用与回收，避免部署密度随时间快速下降。

在存储侧，RootFS、基础镜像、工具盘、依赖和稳定快照状态被组织为 OverlayBD 只读层，并通过内容寻址缓存去重；每个微虚拟机只保存自身的增量写入。磁盘 I/O 使用 ublk、io_uring 和 Direct I/O，减少虚拟机后端与宿主机之间的重复缓存。

在内存侧，同一模板恢复出的不同执行环境共享只读的内存快照。干净页面由宿主机 Page Cache 复用，只有 Dirty/COW 页面和活跃匿名内存成为私有占用。同时，AgentENV 通过 DAMON Reclaim 与 Firecracker Balloon 持续回收 Guest 内部的文件缓存，回收内存资源。

## 将资源稀疏性转化为成本优势

Agentic RL 中的 Agent 执行环境通常按照峰值需求申请资源，却很少同时占满这些资源。我们用“资源分配使用比”这一指标来刻画这种差异：

**资源分配使用比 = 所有****执行环境****声明分配的资源总量 ÷** **宿主机****实际资源使用量**

![[Y2026/Q3/0728_Kimi-K3/assets/Image 6.webp|Image]]

我们统计了生产环境中 70 个节点上 AgentENV 在高负载时段的实际运行数据，样本覆盖约 22.5 万个执行环境。结果显示 CPU 分配使用比平均达到 **27.9×**，最低为 **14.5×**；内存分配使用比平均达到 **9.6×**，最低为 **5.7×**。

这并不是创造了额外资源，而是通过快速暂停与恢复、内存回收以及状态共享，将环境天然存在的空闲时间和重复状态转化为更高的实际部署密度。

![[Y2026/Q3/0728_Kimi-K3/assets/Image 7.webp|Image]]

以 **300 个** **Agent** **执行环境****、每个环境** **4** **vCPU** **和 8 GB** **内存****、连续运行 720 小时** 为例，按观测到的最低资源分配使用比估算，AgentENV 的月度资源成本约为 **1.****53** **万元****。**在图示相同的 CPU 和内存请求口径下，各类按申请资源计费或长期预留资源的方案，估算成本约为 AgentENV 的 **8.8 至 31.7 倍**（容器实例不计入比较范围）。

上述结果基于特定任务负载、资源价格和计费方式，实际成本会随 Agent 执行环境活跃率、内存写入量、环境规格和云平台价格变化。但其说明了一个明确趋势：对于大量有状态、间歇活跃的 Agent 执行环境，成本不应由“创建了多少环境”决定，而应尽可能接近“实际使用了多少资源”。

## 开源共建

随着 Agent 从单轮问答走向代码开发、软件操作、工具调用和长程任务，环境正在成为 Agentic RL 的关键基础设施。隔离性决定训练是否安全可信，环境保真度决定能力能否迁移，而生命周期效率和资源密度则决定训练规模能否持续扩大。

AgentENV 希望通过 Firecracker 强隔离、OCI 镜像兼容、增量快照与 Fork，以及内存和存储复用，为下一代 Agentic RL 提供高效、可靠的环境底座。
