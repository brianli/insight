如果说过去两年，大模型竞争的是知识和推理能力，那么2026年，智能体竞争的则是完成真实任务的能力。

随着基础模型能力持续突破，大模型智能体正加速走出实验室、走向真实生产环境。从个人助手、Coding Agent到科研智能体，Agent的能力边界不断向真实场景延伸。

与此同时，真正决定智能体落地效果的关键，也逐渐从模型本身转向系统能力。工具调用是否精准、长期记忆是否可靠、安全治理是否完善，成为产业界共同关注的三大核心命题。

7 月 2 日，在智猩猩联合主办的 2026 中国 AI 智能体大会开幕式上，天津大学教授、MemoraX AI 创始人郝建业带来了《基于大语言模型的智能体》主题分享。

郝建业教授围绕智能体工具调用、记忆管理、安全治理等关键方向，系统梳理了 Agent 技术的发展趋势，并提出一个核心判断： 基模决定智能体能力下限，Agent Harness 决定能力上限。

在他看来，Agent 的真正价值不在于单次生成能力，而在于能否在真实任务中持续调用工具、沉淀经验，并在安全边界内完成长期协作。

# ***01*** **大模型和智能体的发展  **

首先讲一下当前大模型和智能体技术的发展现状。从2025年到2026年一个非常明显的变化是，随着大模型能力的持续提升，其能力边界也在不断突破。

![[Y2026/Q3/0729_agent-overview/assets/Image 1.webp|Image]]

与此同时，大家对于智能体及其应用方式的认知也在发生变化。从最开始基于基模进行单次工具调用的使用方式，逐渐转换为协作式智能助手，进一步发展到面向更高阶自主执行能力的智能体。

随着基础模型能力的不断增强，我们正在持续拓宽基于模型的智能体所能够带来的能力边界。

# ***02*** **大模型智能体架构  **

## （1）核心架构

大模型智能体的核心架构整体上可以归纳为三个大的方向。

![[Y2026/Q3/0729_agent-overview/assets/Image 2.webp|Image]]

> 上图中，还缺乏几个重要功能模块
> 1. 同用户打交道部分，有着 Message/Channel 部分的内容，即如何处理各种 InboundMessage 和 OutboundMessage
> 2. 同模型打交道部分，有着 Provider/Context 部分的内容，即 Provider 里选择 LLM，而 Context 部分是如何构建 Context 来请求 Model
> 3. 将 User/Model/Tool/Memory等串起来，即 AgentLoop 内容

中间的“大脑”，也就是智能体的核心基模，它决定了智能体单次决策智能的能力上限。

它的外围能力，包括基于各种工具的调用；结合超长上下文处理、记忆管理等机制；以及在面对超长、复杂任务时进一步拓展智能体能力边界的基础上，保证智能体的自主性、执行能力和安全性。

这几个部分共同构成了一个典型的大模型智能体的核心架构。

## （2）范式演进

![[Y2026/Q3/0729_agent-overview/assets/Image 3.webp|Image]]

从智能体使用方式来看，我们同样能看到一个明显的趋势变化。

早期，我们更多是在基础模型上做指令微调（Prompt Engineering）；随后开始转向 Context Engineering；再到现在大家经常提到的 Harness Engineering。

也就是说，我们关注的重点，正在从“如何向模型描述任务”，逐步转变为“如何让模型看到关键的信息，从而更好地理解和遵从指令”，再进一步转变为“如何让智能体在真实环境中持续、可靠、可控地完成任务”。

比较典型的代表就是OpenClaw，今年非常火。本质上，它通过一个统一的 Gateway 入口，让智能体能够调用更多工具，接触更多真实、复杂的场景，从而帮助我们完成更多实际任务。

我们可以看到，可靠的记忆与上下文管理能力，已经成为制约智能体完成长程任务的一个关键短板。

基于这样的背景，后续也出现了一些新一代的“龙虾”框架，例如 Hermes。它最大的特点在于更加注重安全治理能力。同时，它能够将 Skill 进行沉淀并复用，实现自主演化。

# ***03*** 大模型智能体的核心挑战

虽然大模型智能体目前非常火热，但仍然面临三方面最核心的挑战。

![[Y2026/Q3/0729_agent-overview/assets/Image 4.webp|Image]]
- 工具挑战。在长程任务场景下，智能体如何根据当前上下文，自主调用并执行正确的工具，从而保证任务最终能够顺利完成。
- 记忆挑战。如何将长期积累的历史经验有效沉淀下来，实现可校正、可归因以及可持续优化。
- 安全挑战。包括保护用户隐私，以及保障用户物理资产和数字资产的安全，能够真正做到可提取、可审计、可隔离、可回溯。

# ***04*** **大模型智能体的工具调用  **

![[Y2026/Q3/0729_agent-overview/assets/Image 5.webp|Image]]

在工具调用方面，一个比较明显的发展趋势就是从早期基于大模型的编排式调用，逐渐转向“让 Agent 学会在长程任务中主动选择、执行、验证和复用工具”。

所谓编排式调用，就是在上下文中预先设置一些由用户定义好的工具调用范式，让模型按照既定方式执行。

![[Image 6.webp|Image]]

从具体技术演进来看，在2025年之前，主流方式仍然以工作流编排为主，或者结合少量的 SFT 微调方式。之后开始逐渐转向 Agentic RL 的范式，通过强化学习进一步提升智能体的工具调用和任务编排能力。

尤其是在2026年，随着大家对于真实长程任务的需求越来越高，研究重点开始转向构造面向长程任务的 Agentic 任务，并通过 RL 技术进一步提升智能体在长程任务中的工具调用和编排能力。

通用方法包括基于 RL 的工具调用框架。这类方法将工具调用建模为一个复杂的序列决策问题，通过强化学习让模型学习“何时调用工具、调用什么工具、如何填写参数”等关键决策，从而优化工具使用策略，提升多步任务中的推理质量和执行成功率。代表性的工作 Tool-Star 通过更加高效的数据合成、冷启动 SFT 以及多阶段强化学习等方法，进一步提升模型在复杂任务场景下的工具调用能力。

![[Image 7.webp|Image]]

此外，各个基础模型厂商也呈现出同样的发展趋势。比如 Qwen、GLM，包括 Kimi，目前都在基模能力上重点聚焦这个方向。通过构造大量高质量的长程任务，再结合高效的后训练方法，进一步提升基在复杂任务下的工具调用和任务编排能力。

从三个典型应用场景给大家具体介绍。

（1）Search 场景

智能体除了依赖模型自身内化的知识之外，在回答用户问题时，通常还需要结合互联网进行检索，获取外部知识，从而更好地回答用户的问题。

![[Image 8.webp|Image]]

这就要求智能体能够自主学习如何高效检索互联网知识，以及如何利用检索结果完成推理和任务执行。

代表性的工作包括 Search-o1、DualRAG 等。这类方法主要通过任务编排，让智能体借助类似 ReAct 的自主反思机制，学习在不同场景下何时检索、如何检索，以及如何复用检索到的知识。同时，还探索将检索过程中获得的知识沉淀下来，持续优化后续任务表现。

在此基础上，更高阶的方法开始引入强化学习。智能体通过强化学习学会边推理边检索，模型不依赖人工标注的搜索轨迹，而是学习在推理过程中自主决定是否搜索、搜什么、如何利用搜索结果进行推理。

![[Image 9.webp|Image]] 进一步的发展方向是 Deep Research。它关注的是在复杂、超长上下文环境下，如何复用历史调研和搜索信息，帮助智能体判断当前阶段应该采取什么检索方向，以及如何整合已有知识，最终生成高质量的检索结果。例如通义的工作 WebResearcher， 通过一系列复杂的迭代、记忆机制，以及高效的数据合成方法，来实现系统级的 Deep Research 能力。

（2）GUI 场景

这也是大家比较熟悉的，比如手机助手等，GUI Agent 已经成为一个非常高频的应用场景。

![[Image 10.webp|Image]]

在这个场景中，长程工具调用同样是一个非常大的挑战。因此，业界通常会通过构造高质量的沙箱环境，再结合异步强化学习等方式，提升智能体在复杂 GUI 界面下的工具调用和动作执行能力，从而提高整个任务完成和闭环的效率。

![[Image 11.webp|Image]]

比如 Simular Research 这项工作，在已有基础上进一步通过高效地多次并行探索生成候选轨迹，把 GUI Agent 推近人类水平。

（3）Coding Agent 场景

这也是目前可能最重要的一类应用场景。我们看到一个明显趋势是，Coding Agent 正从早期的单次代码生成工具，逐渐转向承担更加复杂的代码工程和软件工程任务。因此，对 Coding Agent 能力的要求也在不断提升。

![[Image 12.webp|Image]]
- 第一个是在基础模型能力方面，各个模型厂商仍然在持续提升模型对于长程、复杂代码生成任务的理解和生成能力。
- 第二个是在此基础上，如何让 Coding Agent 在程序员长期使用过程中，根据用户过往的上下文、使用习惯、Coding 历史记录以及个人偏好，进一步提升后续任务执行效果。

一些比较热门的 Loop Engineering 相关工作，更加强调通过更好的 Loop 编排方式，让 Coding Agent 在复杂任务执行过程中变得更加自主和可控。

# ***05*** **大模型智能体的记忆管理  **

随着智能体越来越走向长程任务，对记忆能力的要求以及它的短板会越来越凸显。大家也越来越意识到，记忆本身是一个非常重要的能力，而且它是独立于基模之外，需要单独具备的核心能力。

![[Image 13.webp|Image]]

记忆管理的技术趋势也是从最早期外挂式的工作流记忆方式，逐渐转向通过学习的方式，实现更加高效的记忆管理。

记忆本身并不是简单的数据存储或者数据管理过程，而是如何像基础模型一样，通过一个“记忆基模”，以模型内化的方式，实现更加高效的全流程、全周期记忆管理。

![[Image 14.webp|Image]]

目前工业界影响力比较大的一个代表工作是 Mem0。它比较典型地采用传统工作流方式，实现整个记忆数据生命周期的编排和管理。最近推出的 2.0 系统，则是在各个环节通过更加高效的工程化优化方式，比如更加轻量化的信息抽取和存储机制、混合检索，以及更加多元化的实体建模方式，进一步提升记忆质量和效率。

比如浙大的相关工作 LightMem 通过一个非常小的压缩模型，进一步降低整个记忆管理过程中的时间开销。还有一些工作则是通过引入强化学习，将整个记忆管理过程建模为一个复杂的决策问题，让智能体通过强化学习方式，学会在不同阶段如何进行检索、抽取、压缩等操作，从而提升整个记忆系统管理的效率。

最近的一些新工作进一步升级，主要是在强化学习算法层面，通过更加高效的奖励信号设计机制，提升模型训练效果。阿里的一项工作 AgeMem，它的主要区别在于，除了前面提到的超长期记忆之外，还进一步引入短期记忆，实现短期、中期、长期记忆的统一管理。

另外，也有一些工作开始探索多模态记忆方向。例如 Seed 相关工作，主要是针对多模态数据，通过高效的记忆管理，提升模型在多模态场景下的推理能力。

我们团队也一直专注于记忆方向的研究。我们主要通过学习模型内化的方式，解决复杂的记忆管理和记忆优化问题。

![[Image 15.webp|Image]]

具体来说，我们关注高效记忆数据的自动化构建，通过一套高效的数据构造引擎，以及基于 Agentic RL 的方式，对记忆模型进行内生优化。同时构建了一套基于归因驱动的自演进学习机制，保证模型能够围绕系统能力提升方向持续优化。

在这个方向上，相比基模能力，目前学术界和工业界都还缺乏非常完善的评测基准。比如在文本记忆、代码记忆方面，目前都还处于比较早期的评测阶段。

因此，我们团队也投入了较多精力进行相关基础建设。过去，我们推出了一些语言类记忆评测基准，包括 LoCoMo-Refined、ScriptMam 等，用于评估模型的记忆能力。

在代码方向，我们也联合高校推出了 SWE Context Bench，以及近期将发布的 CodeMemBenchmark 等评测基准，希望更加贴近真实程序员使用环境，评估长程代码任务中的记忆能力。

![[Image 16.webp|Image]]

同时，我们也打造了一个 Leaderboard，联合牛津、浦江等高校，在语言、多模态以及 Coding 等方向建立评测榜单，近期也会正式发布。也欢迎大家关注和参与，共同推动这个方向的发展。

除了这种显式学习的方式之外，我们认为未来还有一些更加重要的方向，我们也是在重点探索。

![[Image 17.webp|Image]]

比如基于参数化以及隐式的记忆管理方式。它的核心是希望将记忆和知识进一步融入参数空间或者隐空间，实现更加原生、更加模型化的记忆存储、管理和调度。

它可以让记忆能力与基模本身更加一致，更加符合模型自身的特点。在检索效率、推理能力，以及与模型本身的适配程度上，都可能具备更高的上限。

这个方向我们团队也进行了大量探索。不过我们认为，目前距离真正的工业落地可能还有一定距离。但我们相信，它未来可能会成为真正实现 Memory 能力调度的一个核心方向。

# ***06*** **大模型智能体的安全风险  **

随着智能体的发展，同样也带来了更大的安全挑战。实际上，目前已经存在很多安全攻击方式，比如针对 Agent 的直接或间接提示词注入攻击、针对记忆系统的攻击，以及针对工具调用能力的攻击等。

而且，随着智能体能力不断增强，攻击的隐蔽性会越来越高，可攻击的维度也会越来越广。

（1）提示词攻击

恶意指令被嵌入到外部内容中，智能体在检索或读取后可能被操控，执行攻击者意图的操作。

![[Image 18.webp|Image]]

（2）工具层面的攻击

随着智能体能够调用越来越多的工具，一些更加隐蔽、更具组合性的攻击方式，会让以 OpenClaw 为代表的智能体系统面临各种安全隐患。

![[Image 19.webp|Image]]

（3）记忆系统的攻击

智能体的记忆机制可能会遭受到恶意且隐蔽的攻击，并进一步影响用户的数据资产安全。

![[Image 20.webp|Image]]

智能体安全难题已经从 “识别恶意提示” 转向 “在真实环境中约束智能体的长期行为”。因此需要建立多层次的安全防护体系，从输入端的注入防护，到记忆系统、工具调用以及输出环节，都需要构建贯穿全流程的防御体系。

![[Image 21.webp|Image]]

总体来看，这个问题目前可能还没有受到足够多的关注。但我们认为，未来随着智能体的大规模普及，这可能会像过去的软件系统安全问题一样，成为一个必须提前布局和解决的重要方向。

# ***07*** **大模型智能体的应用  **

最后，我简单介绍一些代表性的 Agent 应用，以及我们在这方面开展的一些工作。

（1）个人陪伴场景

现在每天都有各种新的个人陪伴类产品和创业团队出现。在这个场景中，最核心的问题仍然是如何有效管理超长的交流历史数据，从而提升用户沉浸式体验。

我们基于模型能力也开展了相关工作，希望帮助这类产品，无论是生成类产品还是陪伴类产品，都能够进一步提升用户的沉浸式交互体验。

（2）生产力工具类场景

比如以 OpenClaw 为代表的个人助手，包括信息整理、知识助手、Coding、金融助手等一系列应用，以及更广义的办公智能体，比如分析任务、会议纪要整理、会议提醒等。同样，当用户进行深度使用时，面临的核心问题仍然是如何有效管理用户长期积累的历史信息。

我们在 OpenClaw 也进行了大量验证，发现在各种典型用户使用场景下，基于我们的记忆模型可以更好地理解用户，并帮助用户完成更好的提醒、管理、建议、执行等一系列任务。

![[Image 22.webp|Image]]

Coding Agent 也是类似的场景。我们的记忆模型可以通过高效的记忆管理模型，对用户和程序员历史的 PR 记录等信息进行高效理解。在此基础上，帮助用户进行更高效的 Bug 修复，以及生成更高质量的代码。

在医疗领域也是一样。比如慢性病管理场景，需要长期与用户进行交流，了解用户每天的生活习惯、用药习惯等信息。那么，如何对这些超长历史记录进行有效整理，并基于用户真实的历史习惯，提供更加针对性的用药建议和反馈，本质上也依赖于对长期记忆上下文进行精准、高效的管理、理解和利用。

另外，在科研场景，也存在大量超长上下文数据的利用问题。如何通过复杂的工具调用，最终完成复杂科研任务，对工具调用能力以及上下文记忆管理能力都提出了非常高的挑战和要求。

（3）网络安全场景

网络安全场景我认为可以上升到国家战略层面。大家可能比较关注像 Google，包括最近 Claude Mythos 等相关模型的发布，都展示了非常强的安全能力，比如能够攻破目前市场上大量传统软件系统。这既是一件令人惊叹的事情，同时也是一个令人害怕的问题。

![[Image 23.webp|Image]]
